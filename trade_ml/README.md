# Trade ML

> Model training/research for [TradeDesk](../trade_desk). Trains an XGBoost regressor to predict 5-day forward stock returns from ~25 technical/fundamental/sentiment signals per ticker, validates it walk-forward with an embargo gap (no lookahead leakage), then publishes the trained artifacts for `trade_desk` to run live, in-process, on any ticker.

## What this is

A stock is not evaluated in isolation — the model is trained across a broad multi-stock universe (`tickers.txt`), then evaluated and used **per-ticker**, not as a cross-sectional ranker. Per [`log_predictions.py`](log_predictions.py)'s own docstring, the production engine, in order of what actually held up:

- **`return_model.pkl`** (XGBoost, 5-day forward return) — the only model in this repo with a real, walk-forward-validated, bootstrap-CI-excludes-zero edge. The ridge-based master model exists too but is demoted (near-zero betas, unvalidated).
- Quintile (20%) selection, not decile — the only book-size configuration whose bootstrap Sharpe CI excluded zero.
- Inverse-volatility weighting (`std_20`) — confirmed the real lever behind every positive backtest result; equal-weight never won.

This is the model `trade_desk` runs live (see [`../ARCHITECTURE.md`](../ARCHITECTURE.md) for how the two connect).

## Setup

```bash
cd trade_ml
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Pipeline

```
train_return.py  →  publish_artifacts.py  →  trade_desk/models/
                          ↑
              (also needs single_stock_check.csv —
               per-ticker walk-forward track record)

refresh_live_predictions.py  →  trade_desk/models/latest_predictions.json
                                 (current-day snapshot, no retrain)
```

### 1. Train

```bash
.venv/bin/python train_return.py                        # DEFAULT_TICKERS, 15y history
.venv/bin/python train_return.py --tickers AAPL MSFT NVDA
.venv/bin/python train_return.py --days 10               # predict N-day forward return instead of 5
```
Walk-forward validated with an embargo gap (`LOOKAHEAD_DAYS`) between train/test folds to prevent leakage. Writes `models/return_model.pkl` + `models/return_features.json`.

Other training pipelines also live here, each producing its own model — **not** the one `trade_desk` runs live:
- [`train.py`](train.py) — 21-day direction classifier
- [`train_master.py`](train_master.py) — 4-pillar ridge master model (`--alpha` for regularization strength)
- [`train_pead.py`](train_pead.py) — post-earnings-announcement drift model

### 2. Publish to trade_desk

```bash
.venv/bin/python publish_artifacts.py
```
Copies `return_model.pkl` + `return_features.json` into `trade_desk/models/`, and builds `ticker_track_record.json` from `single_stock_check.csv` (the per-ticker walk-forward Spearman rho/p-value results — not generated by a script in this repo; produced by the ad-hoc per-ticker validation run and checked in as data). No live cross-repo import — `trade_desk` only ever reads these finished files at request time.

### 3. Refresh live predictions (no retrain)

```bash
.venv/bin/python refresh_live_predictions.py
```
Builds today's feature snapshot and scores it with the already-trained model — the training cache's own labeled data lags ~3 weeks (21-day label lookahead truncation), so this is what gets `trade_desk/models/latest_predictions.json` current. Run this before `publish_artifacts.py` if you want same-day predictions rather than the training cache's last labeled date.

### 4. Track predictions over time (optional)

```bash
.venv/bin/python log_predictions.py     # scores DEFAULT_TICKERS, logs to predictions.db
.venv/bin/python check_predictions.py   # scores old rows against realized returns, reports hit rate
```
Each logged row is stamped with `return_model.pkl`'s file hash (`model_version`), so historical predictions stay attributable to the exact model that made them even after retraining.

## Ticker universe

`tickers.txt` is this repo's **training** universe (currently 150 tickers) — deliberately decoupled from anything `trade_desk` uses for live scanning (e.g. Top Movers pulls its own S&P 500 list independently). Don't repoint `tickers.txt` at a larger live-scan universe; if `trade_desk` needs a bigger live universe, it should fetch its own list, not widen what this repo trains on.
